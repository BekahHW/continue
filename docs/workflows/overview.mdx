## 🎬 Quick Start Workflows

New to Continue? Start with these simple, high-impact workflows:

### 1. Fix TypeScript Errors in 2 Minutes

**Problem:** Your file has type errors and you don't have time to fix them all manually.

**Solution:**

<Steps>
<Step title="Open the file with errors">
Navigate to the file in your IDE
</Step>

<Step title="Switch to Agent mode">
Click the mode dropdown → Select "Agent"
</Step>

<Step title="Use this prompt">
```
Scan @CurrentFile for TypeScript type errors.
Fix each one and add proper type annotations.
```
</Step>

<Step title="Review and accept">
Agent will show you all fixes. Review and accept the changes.
</Step>
</Steps>

**Time:** 2-3 minutes | **Mode:** Agent | **Difficulty:** ⭐ Beginner

---

### 2. Generate Tests for a Function

**Problem:** You wrote a function but need comprehensive tests.

**Solution:**

<Steps>
<Step title="Highlight the function">
Select the function code in your editor
</Step>

<Step title="Open Agent mode">
`Cmd/Ctrl + L` → Switch to Agent
</Step>

<Step title="Use this prompt">
```
Generate comprehensive unit tests for this function using [Jest/Vitest].

Include:
- Happy path tests
- Edge cases
- Error conditions
```
</Step>

<Step title="Agent creates test file">
Agent will create a new test file with complete coverage
</Step>
</Steps>

**Time:** 3-5 minutes | **Mode:** Agent | **Difficulty:** ⭐ Beginner

---

### 3. Refactor Complex Function

**Problem:** You have a 100-line function that's hard to understand and maintain.

**Solution:**

<Steps>
<Step title="Highlight the function">
Select the entire function
</Step>

<Step title="Use Edit mode">
Press `Cmd/Ctrl + I`
</Step>

<Step title="Use this prompt">
```
Refactor this function:
- Extract logical sections into smaller functions
- Use descriptive names
- Add comments for complex parts
- Preserve all functionality
```
</Step>

<Step title="Review the diff">
Edit mode shows side-by-side comparison. Accept/reject changes.
</Step>
</Steps>

**Time:** 5-10 minutes | **Mode:** Edit | **Difficulty:** ⭐⭐ Intermediate

---

### 4. Understand New Codebase

**Problem:** You joined a project and need to understand how it works.

**Solution:**

<Steps>
<Step title="Open Plan mode">
Switch to Plan mode (read-only exploration)
</Step>

<Step title="Start exploring">
```
Help me understand this codebase:

1. What is the overall architecture?
2. What are the main components?
3. How does data flow through the system?
4. Where should I look to understand [specific feature]?

Use @RepoMap and @Codebase to explore.
```
</Step>

<Step title="Ask follow-ups">
Continue asking questions to dive deeper into specific areas
</Step>
</Steps>

**Time:** 10-20 minutes | **Mode:** Plan | **Difficulty:** ⭐⭐ Intermediate

## 💡 Pro Tips for Workflows

<Tip>
**Combine Context Providers**

Make your workflows more powerful by adding context:

```
Debug this error: @Terminal

In the code: @CurrentFile

After these changes: @Diff

Using patterns from: @Codebase similar error handling
```
</Tip>

<Tip>
**Use Plan Mode First**

For complex workflows, start in Plan mode to explore before making changes:

1. Plan mode: Understand the problem
2. Chat mode: Discuss solutions
3. Agent mode: Implement the fix
</Tip>

<Tip>
**Save Common Workflows**

Turn frequent workflows into [Slash Commands](/customize/deep-dives/slash-commands):

```yaml
slashCommands:
  - name: "debug-error"
    description: "Debug a runtime error"
    prompt: |
      Debug this error: {{{ input }}}

      In: @CurrentFile
      Recent changes: @Diff

      1. Identify root cause
      2. Explain the issue
      3. Fix it
      4. Add error handling
```
</Tip>

## 🎯 Workflow Templates

### General Purpose Template

```
[Problem Statement]

Goal: [what you want to achieve]

Current state:
- [describe current situation]
- @CurrentFile or @File [relevant files]

Expected outcome:
- [what success looks like]

Requirements:
- [constraint 1]
- [constraint 2]

Please:
1. [step 1]
2. [step 2]
3. [step 3]
```

### Debug Template

```
Debugging: [issue description]

Error: @Terminal or [error message]
File: @CurrentFile
Recent changes: @Diff

Please help me:
1. Understand what's causing this
2. Locate the exact problem
3. Implement a fix
4. Prevent it from happening again
```

### Refactor Template

```
Refactoring: [component/function name]

Current issues:
- [issue 1]
- [issue 2]

Goals:
- [goal 1]
- [goal 2]

Requirements:
- Preserve all functionality
- Add tests if missing
- Follow [style guide/best practices]

Code: @File [path] or @CurrentFile
```
